# KHEDMA V34 — Professional Accounts, Work Photos, Password Recovery & Security Hardening

V34 builds on V33 and fixes the main issues found during real testing.

## What V34 fixes

### Professional publishing
- Shows exactly which professional profile fields are missing before publishing.
- A professional cannot become public until the required profile information is complete.
- After saving, the UI reads the actual database state and tells you whether the profile is live or still private.
- Public professional search continues to use real Supabase data.

Required for publishing:
- Full name
- Phone
- WhatsApp
- City
- Service
- Bio

### Work photos
- Professional accounts can upload work photos.
- JPG / PNG / WebP accepted.
- Maximum 6 photos.
- Maximum 5 MB per photo.
- Clear upload errors are shown.
- Delete is handled with storage + database cleanup.
- Storage upload policies are professional-only.

If Supabase reports that the `work-photos` bucket is missing, run the full `supabase.sql` once.

### Reviews and ratings
- Customers submit ratings/reviews.
- Professionals do not rate themselves.
- Professionals see **Customer Reviews**.
- Professional dashboard shows average rating + review count.
- Public professional cards show rating/review count.
- Rating is calculated from real reviews by a database trigger.

### Password security / recovery
- Password field now has an eye toggle.
- Added **Forgot your password?**.
- Supabase password-reset email flow is supported.
- Recovery links return to the KHEDMA site and allow setting a new password.

### Security hardening
- Only customers can create customer requests.
- Only professionals can request verification / PRO.
- Saved professionals and blocks are customer-only.
- Work photo DB/storage writes are professional-only.
- Analytics cannot be written as another visitor/professional.
- Professional leads can only change from `new` to `contacted` or `declined`.
- Match identity and score cannot be changed by a professional.
- Only the first professional who contacts a request becomes the assigned professional.
- Customer lead notifications are generated by the database, not forged by the browser.
- Reports must point to an existing profile/review/request.

## Supabase step for V34

Run the complete `supabase.sql` in:

**Supabase → SQL Editor → New query → paste `supabase.sql` → Run**

V34 SQL is idempotent for the changes it introduces and includes the previous schema sections needed by the project.

## Password reset URL

In Supabase:

**Authentication → URL Configuration → Redirect URLs**

Add the exact GitHub Pages URL of the KHEDMA site, for example:

`https://mouh7229-afk.github.io/KHEDMA-Website/`

The code also uses the current page URL dynamically when requesting a reset link.

## Recommended test order

### 1. Customer
- Use a real customer Gmail.
- Log in.
- Choose a service + city.
- Confirm public search works.
- Create a request.

### 2. Professional
Use a separate Gmail.

- Select Professional at signup.
- Open Profile.
- Fill all required fields.
- Save.
- Publish.
- Confirm the profile becomes visible to the customer.
- Upload 1 JPG/PNG/WebP work photo.
- Confirm it appears in Work photos.
- Open the public profile from the customer account.

### 3. Matching
- Customer request: same service + same city.
- Professional receives the lead.
- Accept/contact the lead.
- Customer receives the notification.

### 4. Reviews
- Customer submits 1–5 stars + comment.
- Professional sees the review under **Customer Reviews**.
- Public rating/count updates.

### 5. Password recovery
- Log out.
- Click Forgot your password?
- Enter email.
- Open the email.
- Set a new password.
- Log in with the new password.

### 6. Admin
Check:
- Professionals
- Requests
- Reviews
- Verification
- PRO
- Moderation

## Important
Do not expose or use the Supabase service-role/secret key in the browser. Only the publishable/anon key belongs in `supabase-config.js`.

V34 should be tested fully before payment integration or public launch.
